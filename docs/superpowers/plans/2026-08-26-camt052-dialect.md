# camt.052 dialect (BBBank) + preview byte-cap

**Owner "Go", 2026-08-26.** BBBank's export format is verified from a real
one-year camt.052 export (issue #6, spec dialect notes updated in the same
commit as this plan). This slice adds the parser, second in the registry
after Revolut, plus the preview byte-cap fix found during verification
(#13). Branch `claude/using-superpowers-wb260x`, TDD per CLAUDE.md, two
atomic commits.

Verified invariants this plan encodes (from the real export — see the
spec's BBBank dialect note): ISO-8859-1 declared in the prolog; single
`TxDtls` per `Ntry`; unsigned `Amt` + `CdtDbtInd` carry the sign;
`AcctSvcrRef` on every entry, globally unique; counterparty name + IBAN
always present; `MndtId`/creditor ID sometimes only as `MREF:`/`CRED:`
tokens in `Ustrd`; booking words in `AddtlNtryInf`; a real page is ONE
physical line of XML.

## Task 1 — `fuck/dialects/camt052.py` (+ registry, vocab, fixture, tests)

Commit: `feat: add camt.052 dialect for BBBank exports`

### Interface (mirrors `revolut.py`)

- `sniffs(sample: bytes) -> bool`: True iff the sample (first 4096 bytes)
  starts with `<?xml` after stripping optional UTF BOM/whitespace AND
  contains `urn:iso:std:iso:20022:tech:xsd:camt.052.` anywhere. camt.053
  and other namespaces do NOT match (add them only when a real file
  demands it).
- `parse(path) -> ParseResult` via `xml.etree.ElementTree.parse` (it
  honors the declared encoding — never re-decode manually). Namespace:
  read the root tag's `{...}` prefix from the parsed root itself rather
  than hardcoding the version string, so a `.001.02` file with the same
  shape still parses.

### Per-report fields (each `Rpt` under `BkToCstmrAcctRpt`; iterate all)

- `iban` = `Acct/Id/IBAN` text; `svcr` = `Acct/Svcr/FinInstnId/Nm` text.
- `source` = first whitespace token of `svcr`, lowercased ("BBBank eG" →
  `bbbank`; fixture "Testbank eG" → `testbank`); fallback `"camt052"`
  when absent.
- `account` = `f"{first token of svcr} {iban[-4:]}"` (fixture:
  `Testbank 3000`); fallbacks: no svcr → `camt052`, no iban → source.
- `Bal` blocks and `RptPgntn` are ignored (page ordering is the caller's
  concern; tx_id dedup makes cross-file overlap safe).

### Per-entry (`Ntry`) rules, in order

1. `Sts/Cd` missing → skip `"malformed"`. `Sts/Cd != "BOOK"` → skip
   `f"state={sts}"`.
2. More than one `NtryDtls/TxDtls` → skip `"unsupported=multi-txdtls"`
   (new controlled-vocabulary reason — add it to `fuck/model.py`'s
   module-docstring skip-reason list in this commit). Zero `TxDtls` is
   fine (bank closings) — parse from entry-level fields.
3. Required: `Amt` text + `Ccy` attr, `CdtDbtInd` (must be `DBIT` or
   `CRDT`), `BookgDt/Dt`, `AcctSvcrRef` (entry-level). Any missing or
   unparseable (`InvalidOperation`, `ValueError`) → skip `"malformed"`.
4. Sign: `DBIT` → negate. `currency = Ccy`; EUR → `amount_eur` = signed
   Decimal; non-EUR → `amount_eur=None` + quality `("non_eur_unconverted",)`.
   `raw_amount` = `f"-{amt_text}"` for DBIT else `amt_text` (sign must
   survive even when amount_eur is None).
5. `tx_id = derive_tx_id(source, iban, acct_svcr_ref)` — AcctSvcrRef is
   the verified rank-1 immutable discriminator; iban scopes it per
   account; no balance, no composite guessing.
6. `payee_raw`: DBIT → `RltdPties/Cdtr/Pty/Nm`, CRDT → `Dbtr/Pty/Nm`
   (the *other* party); fallback `AddtlNtryInf` text; else `""`.
7. `memo` = `"".join` of all `RmtInf/Ustrd` texts, verbatim (the bank
   pre-wraps with in-band spaces; joining with `""` preserves exact text
   and keeps split tokens whole).
8. `booking_type` = `AddtlNtryInf` text or `""`. (GVC codes in
   `BkTxCd/Prtry` are deliberately NOT captured — `AddtlNtryInf` already
   carries the detection words; add GVC only when detect.py needs it.)
9. `mandate_ref` = `Refs/MndtId`; when absent, first regex match
   `r"MREF: (\S+)"` over the joined memo; else None. Same for
   `creditor_id` = `Cdtr/Pty/Id/PrvtId/Othr/Id`, fallback
   `r"CRED: (\S+)"`. (Real export shows the `"MREF: x"` colon-space
   form; support only what is verified.)
10. `payee_norm=""`, `mcc=None` (normalize.py's job later).
11. `SkippedRow.raw` = `ET.tostring(ntry, encoding="unicode")`.

Registry: `REGISTRY = {"revolut": revolut, "camt052": camt052}` in
`fuck/dialects/__init__.py`.

## Task 2 — byte-cap unknown-dialect previews

Commit: `fix: byte-cap unknown-dialect previews`

`fuck/dialects/__init__.py`: the `UnknownDialectError` preview is
line-capped (`PREVIEW_LINES = 3`), but a real camt page is one physical
line — during verification the "3-line" preview dumped ~3.4 KB of real
transaction data (#13). Keep the ≤3-line rule and ADD a total byte cap:
`PREVIEW_BYTES = 300` over the joined preview; when truncation happens,
append ` [truncated]`. Existing short-file behavior (and tests) must be
unchanged.

Two more #13 items ride along because this task already rewrites those
exact lines (next-touch protocol): (a) when the preview is empty (0-byte
file), the message is just `Unrecognized dialect for {name}` — no
dangling `; first lines:` clause; (b) `REGISTRY` gets typed
`dict[str, types.ModuleType]` (it gains its second `.parse()` consumer
in Task 1).

Tests (extend `tests/test_dialects_main.py` or the registry's test home;
RED first): a single-line ~5000-char unknown file → `UnknownDialectError`
message shorter than 400 chars, ends with ` [truncated]`, still names the
file; an empty (0-byte) file → message without `first lines:`; the
existing junk-header test still passes untouched.
